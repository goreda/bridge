# P-A4 BridgeTimeMath spec

Clean-room checked time-math library for media timestamps. Foundation only,
no third-party code, no dependencies beyond the Swift standard library.
Namespace in this package: module `BridgeTimeMath`, error enum
`TimeMathError`, protocol `CheckedTimeMath`, concrete implementation
`Int64TimeMath` (all-static namespace enum).

## Semantics

- `rescale(v, from: srcScale, to: dstScale)`: `v * dstScale / srcScale`,
  round to nearest, halves away from zero. Scales <= 0 throw
  `.nonPositiveScale`. The multiply is checked; the rounding addition
  (`product +/- srcScale/2`, sign of `v`) is checked with the same typed
  `.overflow` - checking only the multiply is a named failure mode of this
  packet. Division is truncating and cannot trap (srcScale >= 1).
  Consequence of the contract: a value whose product fits but whose rounded
  result would land exactly one past Int64.max reports `.overflow` even
  though an arbitrary-precision result would fit (the named regression
  vector 4611686018427387903/4->2 is exactly this case; the negative twin
  -4611686018427387903/4->2 fits and returns -2305843009213693952, and
  -4611686018427387904/4->2 overflows on the subtraction side).
- `splitDuration(total:parts:)`: floor division with a remainder in
  [0, parts) computed once from Swift's truncating `/` and `%` (adjusted
  for negative totals). The first `r` shares are floor+1, the rest floor,
  in order. Sum is EXACTLY total by construction (total = q*parts + r); no
  per-side truncated subtraction anywhere. parts <= 0 throws
  `.nonPositiveParts`. Int64.min totals split exactly (verified by vector).
- `add`/`subtract`: reporting-overflow wrappers, typed `.overflow`, never a
  trap, never a wrap.

## Vectors (deterministic, no randomness)

Tests/BridgeTimeMathTests/Fixtures/: rescale-vectors.csv (43 vectors),
split-vectors.csv (18), addsub-vectors.csv (20). Format per line:
input_fields,expected_value or input_fields,expected_error (split shares
are semicolon-separated). Lines starting with # are comments; the two
required regression vectors are present and named:
- `# regression: rescale-overflow-at-rounding-addition`
  `4611686018427387903,4,2,overflow`
- `# regression: split-int64max-3-parts`
  `9223372036854775807,3,3074457345618258603;3074457345618258602;3074457345618258602`

Coverage: Int64.max and Int64.min inputs; scales 1, 1000, 48000, 12288,
90000, 1000000 (as both src and dst); rounding-addition overflow on both
signs; negative-v symmetry; total=Int64.max with parts=3; parts>total;
single-part identity; halves away from zero on both signs.

Expected values are generated by tools/make_vectors.py with exact Python
big-int arithmetic replicating the checked-naive contract - an independent
oracle, never the Swift implementation. Regeneration is byte-deterministic.

## Assertions (5 tests, green in debug AND release, Swift 5.9.2 ubuntu22.04)

- Every vector passes with the typed result or the typed error.
- Every split vector's shares sum EXACTLY to total (checked add) and each
  share is floor or floor+1.
- Both named regression vectors are present in the CSVs by name and line.
- No vector crashes, traps or wraps; debug and release runs execute the
  identical vectors and agree (both runs recorded in TEST-LOG.txt).
