# P-A6: widened exact oracle matrix, tested partial result

Status: one new exact matrix test passes; one fails explicitly. No skips, no
expected-failure suppression, no library change, no full A6 acceptance.

The delivered P-A1-R2 archive SHA-256 was verified as
`e2864977cddc44b0072fb6efc35a4074dda0d5585dc4b4307d387c083bde9a4b`.
Its existing files, including public protocol and implementations, remain
byte-identical. Original MANIFEST.sha256 still passes GNU sha256sum -c. Added
files are the two synthetic fixture/oracle pairs, A6OracleTests.swift, generation
script, this spec, inspection script and A6Evidence. SHA256SUMS covers the new
complete package except itself; the separate archive digest covers it too.

## Generation and assertion

FFmpeg/ffprobe 4.4.2 Ubuntu 22.04, LC_ALL=C. Exact packet-prescribed generation
commands are in generate-a6-fixtures.sh, with full versions in A6Evidence.
Only local lavfi testsrc2 and sine inputs are used. No media downloads or private
sources. MKV uses the specified libx265 defaults (including B-frame reorder), not
a modified no-B-frame setting. Encoder diagnostics are preserved. Saved ffprobe
-show_streams -show_packets JSON is consumed by XCTest, not run as implementation.
Regeneration can change container IDs, metadata or encoder bytes; delivered
fixtures and oracles are pinned by hashes. Tests do not regenerate them.

New exact tests assert track count/kind/codec, total and per-track packet counts,
and every PTS/DTS/duration in per-track emitted order as reduced exact integer
rationals, preserving nil. Payload sizes are also compared. No timestamp sort,
float tolerance or permitted divergence is used. All mismatches are collected
into JSON before the test fails, so later mismatching fields are not hidden.

## Measured result

Swift 6.0.3 Linux x86_64: 26 XCTest tests executed, 25 passed, 1 failed, zero skips.
All 22 original tests pass. Of four A6 tests, exact MP4, AAC priming, and empty/
truncated safety pass; exact MKV fails. Swift test correctly exits nonzero.

MP4 h264+aac: 143 packets, video 48 and audio 95, matching the saved oracle.
Zero field mismatches. First audio PTS/DTS -1024/48000 and duration 1024/48000
are preserved, covering the generated file's AAC priming edit semantics.

MKV hevc+eac3: 111 packets, video 48 and audio 63, matching the saved oracle.
96 field mismatches, fully enumerated in
A6Evidence/a6-hevc-eac3.mkv.comparison.json:

- 32 HEVC DTS mismatches: implementation always equates DTS to PTS. First video
  packet expects nil but gets 0/1; second expects nil but gets 1/8. Other reordered
  packets also differ. A real HEVC decode/reorder timestamp derivation is absent.
- 1 codec mismatch: track 1 actual a_eac3, expected eac3. The Matroska A_EAC3
  CodecID is not mapped to ffprobe vocabulary.
- 63 EAC3 duration mismatches: every audio packet actual nil, expected 4/125
  seconds (32/1000). EAC3 compressed-frame duration inference is absent.

No other compared field differs. Neither packet counts nor expectations were
invented. A6Evidence contains measured reports and complete failing run log.

## CodecDelay bound and missing coverage

The prescribed generated MKV has no CodecDelay element on either HEVC or EAC3
track, confirmed by structural EBML inspection in tools/inspect_a6_mkv.py and
A6Evidence/mkv-codec-delay.json. Thus this run does not claim nonzero HEVC
CodecDelay coverage. Exact failing fixture/field is a6-hevc-eac3.mkv track 0 DTS,
in addition to EAC3 codec/duration failures. Separate nonzero CodecDelay fixture
coverage would be required to validate that behavior; absence is not a pass for
nonzero delay. The original library subtracts CodecDelay when present but this
packet's generated bytes do not exercise it.

## Safety and reproduction

Empty input throws DemuxError.emptyInput. For both new fixtures, truncations to
1, 4, 16, half-length and length-1 bytes all throw a typed DemuxError without
crash. Original subprocess malformed-input and stale-reopen regressions also
pass. No private sources, UI, playback devices, account operations or network
runtime dependency are involved. This is package/oracle evidence only.
