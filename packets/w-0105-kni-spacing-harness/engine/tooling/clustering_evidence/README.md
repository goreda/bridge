# Clustering evidence transport, proposed v1

Separate module at engine/tooling/clustering_evidence. Delivery tooling is unchanged. Code and synthetic tests only; no production data, sweep, benchmark or physical crash test has run. No CLI is defined. The caller must bind approved source kinds, roles, bounded schema, tree/gate/config/input identity and res-c2-col receipt content. A transport checksum does not authenticate an upstream producer or prove geometry.

## Input attestation

input_attestation.verify accepts typed InputAttestation and SourceRecord objects plus a caller-bound Contract. No self-generated expected hash is trusted. Missing attestation/file/source is NOT_EVALUATED; supplied but unbound snapshot protocol is UNVERIFIABLE. Verified mismatch is a typed AttestationError, not PASS. One fd streams both hashing and parser chunks, with before/after fstat. Consumer must stage results only and discard them on refusal. No parsing schema is supplied here; logical hash remains NOT_EVALUATED. Physical lines count LF plus a nonempty unterminated suffix, including headers/blank lines/BOM bytes. CRLF ends one line. Byte SHA covers every byte. Parsed-record count is separate and not implemented.

Cooperative shared lock is optional and grants only the declared all-writers-honor-lock protocol. Without it snapshot_status is UNVERIFIABLE even if hash/count match. It cannot stop a malicious or noncooperative writer, and fstat does not prove absence of same-size in-place mutation. SourceRecord is a supplied typed provenance claim checked for exact equality, not independent authorship authentication.

## Canonical receipts and framing

Encoding name: kni.clustering-receipt-canonical.v1. No JCS claim. Fixed ASCII keys, recursively byte-sorted; Unicode scalar string values preserved without normalization, UTF-8, compact JSON, integer/string leaves only. Floats/bools/null/surrogates/duplicate keys rejected. Integers are schema-bound i64; larger fields must be string-typed from schema inception, never dynamically converted by value. Arrays preserve order. Binary64 data requires separately bound float_receipt hex-string semantics; none are invented here. RFC8785 sorting uses UTF-16 and its numeric handling differs: https://www.rfc-editor.org/rfc/rfc8785 . This module does not implement RFC8785.

Frame format convention: version byte 0x01, sequence u64 BE (first 1), payload length u32 BE, canonical payload, checksum 32 bytes. Payload includes previous_frame_sha256 as a lowercase 64-character hex representation of the 32-byte previous frame hash; first is all zeros. Checksum=SHA256(sequence||length||payload), not version. Frame hash for chain/anchor=SHA256(entire encoded frame including version and checksum). This implements the final replacement decision; there is no second checksum or external prev field.

Every frame wraps receipt and previous_frame_sha256. Receipt names schema_version, tree_sha256, gate_id, gate_config_sha256, input_sha256s, c2_source, tagged res_c2_col, status, co_gate_status and logical_hash_status. Absent res-c2 is tag absent with empty value, not zero/null. Status UNVERIFIABLE is never PASS. Missing co-gate input/calculation is NOT_EVALUATED. Supplied evidence that cannot be checked is UNVERIFIABLE. A supplied PASS is only structurally screened against required fields/co-gate status, not validated as a true gate computation. Callers must not equate successful append/transport verification with gate PASS.

## Bounds and locking

schema_bound derives a conservative maximum canonical payload size from a supported CLOSED bounded-schema subset, including escape expansion, every string min/maxLength, array min/maxItems and integer min/max. It rejects unknown types, unbounded properties or u32 overflow. Supported schemas are exact-key objects, arrays, integers and strings; JSON Schema is not fully implemented. The included schema/synthetic-frame-v1.schema.json has TEST-ONLY count/length conventions, not production limits. Production schema/policy binding is still required. No guessed production payload cap is provided.

One advisory-lock writer per local Linux POSIX file, held over read/check/append/fsync. fstatfs allowlist: xfs, btrfs, tmpfs. ext4 is architecturally allowed, but ext2/ext3/ext4 share statfs magic, so this implementation refuses ext-family until ext4 identification has a grounded implementation. Other filesystems/platforms refuse, no unlocked fallback. Lock timeout/poll bound are caller parameters. Parents must exist and be stable/trusted; O_NOFOLLOW protects the final path component only. This is not an adversarial shared-directory storage protocol.

Idempotency key uses schema_version, tree/gate/config hashes, input hashes, C2 source and res-c2 state. Same key and canonical receipt hash is no-op; same key/different bytes is typed conflict. Appends use full-write loop, file fsync and parent-directory fsync before acknowledgement. New anchor must be persisted independently by caller; storage never treats it as an already trusted external anchor. Without an external anchor, tail_completeness is UNVERIFIED, never PASS. Frame-boundary tail loss is undetectable without such an anchor.

Partial/corrupt trailing frames are refused, never truncated or silently repaired. Checksum/sequence/chain/anchor mismatch refuses. A damaged length can mimic a torn tail; ambiguous errors are named incomplete_or_corrupt_tail. Unknown fsync outcome is not retried automatically. This Python implementation reads existing history into memory; no streaming scale or large-corpus capacity claim. No power-loss durability proof, anti-rollback security or malicious-writer protection is claimed.

## Tests and integration

From engine/tooling: `python3 -m unittest discover -s clustering_evidence/tests -t . -v`.
Use package imports (`clustering_evidence.input_attestation` and `.receipt_storage`) with engine/tooling on the Python module search path; direct script execution is not supported. Relative internal imports do not depend on a bare-module sys.path hack. Test discovery uses package __init__.py files.

Synthetic tests mock the filesystem probe ONLY in transport/attestation mechanics tests, so they need no tmpfs mount; those tests do not qualify the actual filesystem. Production filesystem refusal remains active. Fault injection proves partial writes are not silently accepted or repaired. A failed create can leave an empty file; a partial append can leave an incomplete trailing frame, and failed fsync can leave an unknown committed outcome. These require manual, separately reviewed recovery before further append. The module never truncates history automatically, even on its own failed append. Retry first reads and validates the existing log; an identical fully committed record is idempotent, but a torn frame refuses. No automatic rollback is promised.

Production source/role policy, bounded real schema, logical hashing, external anchor storage, ext4 identification and physical durability qualification remain separate requirements. Supplied synthetic bounds are not production defaults. No geometry/gate acceptance follows from transport tests.

Manual recovery procedure: stop all cooperating writers; preserve the original file and any external anchor as immutable evidence; independently validate the complete prefix and identify the first refusal (`incomplete_or_corrupt_tail`, `corruption`, `chain`, `sequence`, or `anchor_mismatch`). Do not edit/truncate the original. Obtain a separately reviewed recovery decision naming any new log path and external-anchor reconciliation. A complete frame after a reported fsync failure must be reconciled as an unknown durability outcome, not blindly re-added. This module implements no recovery-copy or suffix-repair command. File descriptors are closed on error; close is not a substitute for fsync success.
