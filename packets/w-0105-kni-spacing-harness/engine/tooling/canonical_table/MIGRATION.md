# Explicit canonical input migration

Uses the canonical_table_build module in this directory. Only synthetic fixtures are included; no real input is part of the repository. Run the tests from this directory with `python -m unittest -v test_migrate_canonical_inputs.py`. Rust is not involved.

Plan remains canonical-table-migration-v1; target is explicit canonical-table-input-v1. Both plan source.sha256 and target file.sha256 must match the CURRENT legacy raw bytes before transformation. Every TSV source must declare rows (physical data-line count). The output manifest replaces these current source hashes with new hashes. Missing current target hash is an error, not permission to invent one.

TSV transport is raw physical-line prefixing, not CSV quoting. Preserves every legacy line byte including quote characters, CRLF/LF, final newline presence, UTF-8 BOM and empty fields. Prefixes schema_version and the version on each data row only. Quotes have no special escape semantics. Embedded physical newlines are unsupported. Header must exactly match the explicit source header, and target header can only prepend schema_version. Blank physical rows, wrong field counts and declared row-count mismatch are rejected, never silently dropped. Header-only TSV requires rows=0.

JSON duplicate keys and NaN/Infinity/-Infinity are rejected in source, plan and target inputs. Number tokens are retained separately from strings and re-emitted verbatim: 1.7000, 1e+09, -0 and long integers stay numeric with exact lexical tokens. JSON key order and whitespace may change; scalar string values remain strings. No float round-trip. Optional embedded SHA changes must be listed by exact metadata path and source ID, point to TSV sources and verify the old value. After explicit rewriting, every JSON string is recursively scanned for any migrated legacy SHA substring; any remaining occurrence, including an unlisted nested/list binding, rejects the migration. This conservative scan can reject a prose mention of an old digest; it will not silently leave one behind. JSON-to-JSON dependencies remain unsupported.

Output is staged and published into a new directory, with new manifest and migration receipt. No measurement or builder run. Publication rechecks destination existence but does not claim race-free no-replace semantics across concurrent writers; use exclusive destination ownership. Existing directories must not be overwritten. The receipt distinguishes schema-only changes from explicit SHA binding updates.

The synthetic tests cover raw quotes/BOM/CRLF/empty fields, blank row and count guards, stale current target digest, lexical JSON numbers, duplicate keys/nonfinite values and nested stale SHA scan, alongside prior explicit bindings, checksums and destination/header/schema guards. No third-party or real data fixtures.
