## W-0225  line-context glyph size and case-pair resolver (posted 2026-10-28 Europe/Istanbul)
state: posted 2026-10-28 Europe/Istanbul. solver: 1nstinct (g-). reviewer: in2tinct (h-), failure cases first, without reading the fix (123d). One id for its whole life (123c).

problem (what fails for the user): a risk, not a proven sole cause: when a glyph is cut to a tight ink box before identification, absolute size is lost, so pairs that differ mostly by scale (c/C o/O s/S u/U v/V w/W x/X z/Z p/P and similar) can come back as the wrong case, and a lone shape gets one confident-looking letter guess. Needed: a small pure module that, given the regions of ONE text line (boxes plus the tight-crop ink heights, from the page before tight cropping), measures relative ink-height groups without claiming these are semantic x-height or cap-height and returns, per region, one of: lower-like, upper-like, or unresolved, with the measured ratio. A region that is alone on its line, has too few neighbours, or whose measured heights do not separate into two clusters must return unresolved. It must not return a letter and must not assign Unicode.

reproducer: no owner images, no owner fonts. Use only OFL fonts at the pinned google/fonts commit 9862abc066c9b83bf84c3e8ed1fc2d8d48f9bbf0 already on the bridge. Design and threshold work uses the 5 calibration families only; the 5 validation families judge once; the 5 baseline test and the 24 added test-only families stay sealed for development and acceptance tuning (frozen holdout policy) and are used only for one final descriptive check after the code is frozen. Render to synthetic lines at several em sizes (256/384/512 px frames) and mixed-case word strings built from the 62-class set. Rendering and tight-crop code: the W-0224 harness on lab/w-0224-results.

expected behaviour: (1) return only geometric lower_like / upper_like hints or unresolved, never a case classification. Choose any grouping thresholds or minimum support on calibration families only and report abstention; (2) identifiability: boxes and ink heights alone cannot tell all-caps from all-lowercase or identify ascenders/descenders. Two height clusters alone are not proof of case. Baseline_y and top_y are positional references, NOT semantic x-height/cap-height anchors. Without independent semantic evidence, a hint must remain explicitly geometric and cannot resolve identity; (3) all-same-height lines, single/two-glyph lines, and rotated/uneven baselines return unresolved. Never force all-upper or all-lower; (4) deterministic, stdlib plus numpy only, no weights, no network.

call site and interface: resolve_line_case(regions, line=None) -> list[{label: "lower_like"|"upper_like"|"unresolved", ratio: float|None, reason: str}]. regions is list[{x0,y0,x1,y1,ink_h}] for ONE line in page pixels (y increases down); line is optional {baseline_y:int, top_y:int}, or None when unknown. This is the exact signature in case_resolver.py. Called after line segmentation, before per-glyph note text; hints are geometric advisory only, never case proof.

must not change: per-glyph classifier input and outputs; no identity or Unicode is derived from the hint; unresolved is not a failure; no existing threshold is replaced.

acceptance test: supplied pure-geometry safety tests must pass; these do not prove letter case. Solver supplies an OFL synthetic-line harness covering mixed heights, all-lower x-height-only, all-upper, single/two glyphs and descender-heavy lines. Design on calibration families only; judge validation families once without retuning. Baseline 5 test and added24 test-only families stay sealed for selection and acceptance tuning, used only for one frozen final descriptive check. Report geometric grouping/abstention per family, whole-family bootstrap intervals, and separately any descriptive association with known render-case labels without claiming case proof. A one-glyph line always returns unresolved.

delivery: version, start commit, patch, run command, test output under one delivery id (123e). Fixture and metadata results are plumbing only; no recognizer accuracy is claimed from them.
